Why this session

Current state

Anecdotes detects violations across 25 applications on a weekly cadence. Results stay inside Anecdotes. Auditors pull reports from there. Remediation is manual — someone spots a violation, creates a Jira ticket.

The gap (now closed)

Anecdotes violation data was not flowing into Snowflake. As of August 2026, the data share is configured and RBAC grants are in place.

What we build today

A compliance monitoring app built on Cortex AI end-to-end: AI functions enrich violations at ingest, Cortex Analyst makes them queryable in plain English, Cortex Search puts runbooks at your fingertips, a Cortex Agent ties it all together, and guardrails govern what goes in and what comes out.

Cortex AI isn't a feature we bolt on — it's how we build the app and how Jordyn uses it.

Snowflake Cortex AI — building blocks

AI_CLASSIFY

Categorize violations into risk types: Data Exposure, Access Control, Configuration Drift, Policy Non-Compliance, Operational Gap.

AI_EXTRACT

Pull structured entities from violation descriptions: affected systems, users, roles, protocols, compliance frameworks.

AI_COMPLETE

Generate one-line actionable summaries from verbose violation descriptions. Turns paragraphs into action items.

Cortex Analyst

Semantic view turns natural language into SQL. "How many critical violations are overdue?" → instant answer.

Cortex Search

25 remediation runbooks indexed and searchable. "How do I fix an MFA violation?" → step-by-step guide.

Cortex Agent

Combines data queries + runbook search in one chat interface. Compound questions like "show violations and how to fix them."

AI enrichment — 3 functions

AI_CLASSIFY

AI_CLASSIFY(
  v.DESCRIPTION,
  ARRAY_CONSTRUCT(
    'Data Exposure',
    'Access Control',
    'Config Drift',
    'Policy Non-Compliance',
    'Operational Gap'
  )
):"label"::TEXT

AI_EXTRACT

AI_EXTRACT(
  v.DESCRIPTION,
  ARRAY_CONSTRUCT(
    OBJECT_CONSTRUCT(
      'name', 'systems',
      'description',
      'Applications mentioned'
    ),
    OBJECT_CONSTRUCT(
      'name', 'users',
      'description',
      'Usernames mentioned'
    )
  )
)

SNOWFLAKE.CORTEX.COMPLETE(

Before we start

1. This workshop uses synthetic violation data — realistic patterns modeled on Anecdotes output, but no real compliance data.

2. The Anecdotes data share is live (Aug 2026) — once we're comfortable, we can point everything at real data.

3. Strongest hook for Jordyn: the agent combining violation queries with remediation runbooks. "Show me critical violations and how to fix them" in one question.

4. SLA thresholds used throughout: CRITICAL = 3 days, HIGH = 14 days, MEDIUM = 30 days, LOW = 60 days.

5. Cortex AI theme: every workshop in this series uses Cortex AI both to build the app and to let users interact with it. This one is no different — AI functions, Analyst, Search, Agent, guardrails.

6. Everything is live — data is in Snowflake, semantic view and agent are deployed, Streamlit app is ready. Let's go.
